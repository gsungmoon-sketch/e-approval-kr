백업·복구

백업은 문서 원문·첨부·사원 정보가 모두 들어 있는 zip 파일 하나입니다. 서버가 켜져 있어도 만들 수 있습니다.

자동 백업

첫 설정에서 백업 폴더를 정하면 서버가 매시간 확인하여 하루에 한 번 e-approval-kr-YYYYMMDD-HHMMSS.zip 파일을 만들고, 이 이름 형식의 파일을 최근 14개만 남깁니다(다른 이름의 파일은 건드리지 않음). 설정 직후 첫 백업은 최대 1시간 안에 생깁니다. 보관 개수는 데이터 폴더의 server.json에서 "backup_keep"(1~365)로 바꾸고 서비스를 다시 시작합니다. 폴더는 서버와 다른 디스크에 두세요. 일주일에 한 번은 외장 디스크나 다른 PC로 복사해 두면 더 안전합니다.

점검 습관자동 백업이 실제로 만들어지는지 가끔 백업 폴더를 열어 날짜별 파일이 쌓이는지 확인하세요.

수동 백업

관리자용
e-approval-kr backup 2026-11-13.zip
데이터 위치를 직접 줄 때: e-approval-kr --data <데이터폴더> backup 파일.zip
백업 파일은 민감 정보입니다문서와 개인정보가 들어 있으므로 암호화된 저장소(예: 암호를 건 외장 디스크)에 두고, 아무나 열람하지 못하게 하세요.

복구

  1. 서버를 멈춥니다(Windows 서비스 중지 / sudo systemctl stop e-approval-kr).
  2. 빈 폴더에 복구합니다. 기존 데이터 위에는 복구되지 않습니다. 기존 데이터 폴더는 지우지 말고 이름을 바꿔 보관하세요.
  3. 복구가 끝나면 자동으로 감사로그를 검증합니다.
  4. 복구한 폴더를 서비스가 쓰도록 하고(또는 기존 폴더 위치에 놓고) 서버를 시작합니다.
관리자용
e-approval-kr restore 2026-11-13.zip --to /경로/새-빈-폴더
서비스 설치본의 데이터 폴더는 설치 페이지의 위치를 보세요. Linux에서는 복구 후 폴더 소유자를 e-approval-kr 사용자로 맞춰야 합니다(sudo chown -R e-approval-kr: 폴더).

감사 머리값 보관

감사로그는 서로 이어진 해시(체인)로 되어 있습니다. 데이터 폴더를 마음대로 고칠 수 있는 사람은 체인 전체를 다시 만들 수도 있으므로, 현재 체인의 머리값(번호와 해시)을 정기적으로 다른 곳에 적어 두면 그런 시도까지 잡아낼 수 있습니다.

관리자용
e-approval-kr export-audit-head              # 번호와 해시 출력 → 다른 곳에 보관
e-approval-kr check-audit-head <번호> <해시>   # 보관한 값이 그대로인지 확인
e-approval-kr -u admin verify-audit          # 체인·완료문서 변조 검증

권장 주기: 월 1회 머리값을 보관하고 검증을 실행합니다.

새 버전으로 올리기

새 버전을 설치해도 데이터는 그대로 유지됩니다. 그래도 항상 먼저 백업하세요.

  1. 백업: 수동 백업을 한 번 만들고 안전한 곳에 복사합니다.
  2. 사용이 적은 시간(퇴근 후 등)을 고르고 직원에게 알립니다. 서버는 잠깐 멈춥니다.
  3. 새 설치 파일을 받아 실행합니다. 같은 방식으로 한 번 더 설치하면 됩니다.
    • Windows: 새 setup-<버전>-win-x64.exe 실행(SmartScreen 안내는 동일). 제거할 필요 없음.
    • macOS: 새 .pkg 설치.
    • Linux: 새 tar.gz를 풀고 sudo ./install.sh(처음에 --lan을 썼다면 같이 지정).
    • pyz: 새 파일로 바꿔 실행.
    • Docker: 새 이미지를 만들고 같은 볼륨으로 컨테이너를 다시 실행.
  4. 접속해 로그인되는지, 최근 문서가 보이는지 확인합니다. /healthz도 확인합니다.
  5. 문제가 생기면 이전 버전을 다시 설치하거나, 백업을 복구합니다.
설정은 유지됩니다접속 범위·포트·백업 폴더는 데이터 폴더의 server.json에 있어 업그레이드해도 그대로입니다. 다만 새 설치 파일이 서비스 설정을 새로 쓰므로(Linux는 --lan·--port 옵션을 처음처럼 다시 지정), 업그레이드 뒤 다른 PC에서 접속되는지 한 번 확인하세요.
관리자용업그레이드 직후 e-approval-kr -u admin verify-audit로 감사로그 이상 없음을 확인하세요.
