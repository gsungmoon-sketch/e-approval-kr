관리자 설명서

관리자 계정으로 로그인하면 관리 메뉴가 보입니다: 사원 / 부서 / 직위·서열 / 규정·전결 / 양식 / 변경요청·설정 / 외부 메일 / 감사로그 (CSV 가져오기는 사원 화면 아래). 관리자는 사원·규정·감사를 관리하지만 남의 문서 본문을 볼 권한은 없습니다.

1. 설정 순서

  1. 부서 → 2. 직위·서열 → 3. 사원 → 4. 결재규정 → 5. (선택) 양식 조정 → 6. 외부 메일

2. 부서

관리 → 부서에서 부서코드(영문, 예 DEV)와 이름(예 개발팀)을 등록합니다. 이름 변경, 사용중지/재사용이 가능합니다. 사용중지해도 기존 문서는 남습니다.

관리자용
e-approval-kr -u admin dept add DEV 개발팀
e-approval-kr -u admin dept list
인자 순서는 dept add --help로 확인하세요.

3. 직위·서열

직위는 영문 코드(소문자로 시작)와 이름, 서열(높낮이)로 구성됩니다. 서열은 결재선(누가 위인지)과 전결에 쓰입니다. 회사에 맞게 추가·수정할 수 있습니다. 부서장급 직위를 새로 부여하는 일은 2인 승인 대상일 수 있습니다(아래).

4. 사원

관리 → 사원에서 등록·수정·부서이동·직위변경·재직/휴직/퇴사 처리를 합니다.

  • 사번은 비워 두면 자동 발급(입사일 YYMMDD + 일련번호, 예 2026-11-13 입사 → 26111301). 로그인 아이디 기본값도 사번입니다.
  • 임시 비밀번호는 등록할 때 한 번만 화면에 보입니다. 바로 전달하세요. 사원은 첫 로그인에서 바꿉니다.
  • 퇴사 처리하면 로그인이 막히고 문서·기록은 보존됩니다.
  • CSV 일괄 등록: 사원 화면의 가져오기. 열 이름은 사번, 이름, 부서, 직위, 아이디, 이메일, 전화, 입사일, 상태, 직책. 먼저 미리보기로 오류를 확인한 뒤 반영합니다. UTF-8과 엑셀(CP949) 파일을 모두 읽습니다. 내보내기도 있습니다.
  • 비밀번호 재발급: 사원 화면 또는 CLI로 새 임시 비밀번호를 만듭니다.
관리자용
e-approval-kr -u admin emp add --name 홍길동 --dept DEV --position 팀원 --hired 2026-11-13
e-approval-kr -u admin emp import 사원.csv           # 미리보기
e-approval-kr -u admin emp import 사원.csv --apply   # 반영
e-approval-kr -u admin emp resetpw 26111301
e-approval-kr -u admin emp retire 26111301
e-approval-kr -u admin setting set emp_digits 3     # 자동 사번 일련번호 3자리

5. 결재규정 (부서별)

관리 → 규정·전결에서 부서마다, 문서 종류(일반·지출·휴가)마다 정합니다. 규정이 없는 부서는 "자유 결재선"으로 기안자가 직접 결재선을 만듭니다.

항목뜻
결재선직위 순서. 예: 팀장?, 부서장, 대표. 물음표(?)는 "그 직위 사람이 없으면 건너뜀", @아이디는 특정인 지정.
전결 한도직위별 금액 한도. 예: 부서장:100만, 임원:500만. 금액이 한도 이하이면 그 직위에서 결재가 끝납니다.
추가 결재자 허용기안자가 결재선에 사람을 더 넣을 수 있는지(예/아니오).
필수 참조반드시 참조에 들어갈 사람(아이디). 예: 인사팀.
대결 규칙대결 허용 여부, 같은 부서만 허용, 대결자의 최소 직위, 최대 기간(일).
  • 규정은 버전 관리됩니다. 바꾸면 새 상신부터 적용되고, 진행 중 문서는 상신 당시 규정을 유지합니다.
  • 미리보기로 "이 부서·종류·금액이면 누가 결재하나"를 확인한 뒤 적용하세요.
  • 금액 한도 전결은 양식 문서에 적용되지 않습니다 — 서버는 양식의 금액을 꺼내 계산·확인하지 않으며, 결재자가 금액을 확인합니다. 한도 없는 전결 규칙과 전체 결재선은 그대로 적용됩니다. (자유 형식 기안에 --amount를 직접 준 경우만 한도 전결이 적용됩니다.)
관리자용
e-approval-kr -u admin policy edit DEV --type 지출 --line "팀장?, 부서장, 대표" --jeon "부서장:100만" --cc hr
e-approval-kr -u admin policy deleg DEV --allowed yes --same-dept yes --max-days 14
e-approval-kr -u admin policy preview --dept DEV --type 지출 --amount 150만
e-approval-kr -u admin policy show DEV ; e-approval-kr -u admin policy history DEV
e-approval-kr -u admin policy clear DEV      # 규정 해제(자유 결재선)

6. 양식 관리

관리 → 양식에서 목록을 보고 새 양식 만들기, 복사, 수정, 사용중지를 합니다. 기본 양식 10종(일반기안(품의), 업무보고, 지출결의서, 구매요청서, 출장신청서, 출장비정산서, 경비정산서, 휴가신청서, 협조전, 공문)은 복사해서 고쳐 쓰는 것이 편합니다.

버전

양식을 수정하면 새 버전이 만들어집니다. 이미 기안된 문서는 기안 당시 버전 그대로 보입니다. 더 이상 쓰지 않을 양식은 지우지 말고 사용중지하세요.

관리자용
e-approval-kr -u admin form list
e-approval-kr -u admin form copy general hr_memo --name "인사 품의"
e-approval-kr -u admin form edit hr_memo 정의.json    # 새 버전
e-approval-kr -u admin form add edu 정의.json

기본 부서 분류

양식 화면 아래 기본 부서 분류에 분류 이름을 적으면, 그 양식으로 기안할 때 기안자 부서의 같은 이름 분류가 기본으로 골라집니다(없으면 일반). 비우면 자동(지출·경비 → 회계, 휴가·출장 → 인사, 구매 → 비품, 그 밖 → 일반). 새 버전을 만들지 않습니다.

문서관리 담당

사원 상세의 문서관리 담당 지정을 켜면 그 사원은 자기 부서 문서(볼 수 있는 것)의 분류·사업을 결재가 끝난 뒤에도 바꿀 수 있습니다. 부서 분류 나무는 문서함 → 부서 문서함 → 분류 관리에서 부서장·관리자가 고칩니다(관리자는 부서 코드를 바꿔 다른 부서도).

7. 문서번호 형식

최종 승인 때 번호가 붙으므로 결번이 생기지 않습니다. 기본 형식은 {dept}-{year}-{seq}(예 DEV-2026-0001). 쓸 수 있는 자리표시자: {dept} 부서코드, {year} 4자리 연도, {yy} 2자리 연도, {prefix} 양식 접두어(없으면 부서), {seq} 일련번호.

관리자용
e-approval-kr -u admin setting list
e-approval-kr -u admin setting set doc_number "{prefix}-{year}-{seq}"
e-approval-kr -u admin setting set show_contacts on   # 조직도에 이메일·전화 공개
setting list에서 현재 형식 문자열을 확인할 수 있습니다. 자유 기안(양식 없이 쓰는 기안)은 기본으로 꺼져 있어, 쓸 수 있는 양식이 있으면 모든 기안은 양식으로 시작합니다(지출을 일반 문서로 올려 전결 한도를 피하는 것 방지). 꼭 필요하면 setting set allow_freeform on. 새 형식은 이후 완료되는 문서부터 적용되며 이미 부여된 번호는 바뀌지 않습니다.

8. 2인 승인

켜 두면 결재규정 변경, 관리자 지정, 부서장급 직위 부여 같은 중요한 변경이 다른 관리자의 승인을 받아야 적용됩니다. 한 사람의 실수나 악용을 막습니다. 관리자가 2명 이상일 때 켜세요. 승인 대기 건은 관리 → 변경요청·설정에서 다른 관리자가 승인 또는 거절합니다.

관리자용
e-approval-kr -u admin setting set two_person on
e-approval-kr -u admin2 change list
e-approval-kr -u admin2 change approve <번호>   # 터미널에서 본인 비밀번호를 물어봄
e-approval-kr -u admin2 change approve <번호> --password-file pw.txt   # 스크립트용(첫 줄 = 비밀번호, '-' = 표준입력)
요청한 본인은 승인할 수 없고 다른 관리자만 승인합니다. CLI에서는 본인 확인을 위해 승인·거절 때 그 관리자의 비밀번호를 입력해야 합니다. 관리자가 2명 미만이면 2인 승인을 켤 수 없습니다.

9. 외부 메일 (SMTP)

기본은 꺼짐입니다. 켜면 결재 도착·완료·반려 알림이 사원 정보의 이메일 주소로 나갑니다. 사내 메일을 외부 주소로 보내는 기능은 따로 허용해야 하며 시간당 발송 한도가 있습니다. 받는 메일 서버 기능은 없습니다(보내기만 함).

  1. 관리 → 외부 메일을 엽니다.
  2. 회사 메일 서비스의 SMTP 서버, 포트(예 587), 보안(STARTTLS), 아이디, 비밀번호, 보내는 주소를 입력합니다. Google Workspace는 앱 비밀번호가 필요합니다.
  3. 시험 발송으로 확인한 뒤 사용을 켭니다.
주의SMTP 비밀번호는 데이터 폴더의 smtp.json에 저장됩니다. 데이터 폴더와 백업 파일을 아무나 열 수 없게 하세요.
관리자용
echo '앱비밀번호' | e-approval-kr -u admin smtp set --host smtp.example.com --port 587 --security starttls \

10. 감사로그와 검증

관리 → 감사로그에는 모든 상태 변경(상신·승인·반려·권한 변경 등)이 해시 체인으로 기록됩니다. 완료된 문서는 내용 해시도 남아, 몰래 고치면 검증에서 드러납니다.

  • 정기적으로(예: 월 1회) 검증을 실행하세요.
  • 더 안전하게 하려면 "체인 머리값"을 다른 곳(다른 PC, 메일, 인쇄)에 보관하세요. 데이터 폴더에 쓸 수 있는 사람이 체인 전체를 다시 만드는 경우까지 잡아낼 수 있습니다. 자세한 절차는 백업·복구.
