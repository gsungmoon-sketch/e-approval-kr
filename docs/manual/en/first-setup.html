First setup wizard

After installation your browser opens http://127.0.0.1:8130/setup. If it does not, type the address yourself. Setup can only be done on the computer where the server is installed; other PCs are blocked for safety.

Step 1. Create the first administrator

  1. Enter an ID (for example admin), a name (for example 관리자), and a password.
  2. Choose a long password that is hard to guess and keep it somewhere safe. If you lose it, an administrator must reissue it with the CLI.

Step 2. Who can connect (bind address)

ChoiceMeaningWhen
This computer only (127.0.0.1)Only a browser on this computer can connect.Alone, or testing. Default and safest.
Office network (LAN) (0.0.0.0)Other PCs on the same office network can connect.When staff share the server.
WarningThe wizard shows a warning when you choose the LAN. Plain HTTP can be read by other people on the same network, so put an HTTPS reverse proxy in front. Opening the server directly to the internet (router port forwarding) is not recommended.

After changing the bind address, restart the service for it to take effect.

  • Windows: open Services (Win+R, services.msc), right-click e-approval-kr, Restart.
  • macOS: restart the Mac or use the launchctl commands.
  • Linux: sudo systemctl restart e-approval-kr

Step 3. Choose a backup folder

Pick the folder where backups are stored. A backup is made automatically once a day and the latest 14 are kept (older ones are removed). The first backup is made right when setup finishes (you get an error if the folder is not writable). Choose a folder on a different disk from the server if you can (external drive, network storage); if the server disk fails, backups on the same disk are lost with it. See Backup and restore.

Wizard fields and where they are stored

FieldNotes
Administrator ID, name, passwordPassword: 8 characters or more, typed twice.
Admin department code and nameThe department the first administrator belongs to (default ADM / 관리부). Can be changed later.
Who can connect, portThis computer only (127.0.0.1) / office network (0.0.0.0); default port 8130.
Backup folderEmpty means no automatic backup.
  • Bind address, port and backup folder are saved in server.json in the data folder (host, port, backup_dir, backup_keep). serve without options reads it. serve --host ... --port ... on the command line wins.
  • When setup is finished the /setup address turns into the sign-in page (it never opens again once a user exists). http://127.0.0.1:8130/healthz returns {"ok": true, "version": "..."} at any time (useful for monitoring).
  • On Linux, if you used --lan or --port at install time, the service drop-in listen.conf overrides server.json. To use server.json again delete /etc/systemd/system/e-approval-kr.service.d/listen.conf and run sudo systemctl daemon-reload && sudo systemctl restart e-approval-kr.
  • Opening /setup from another PC only shows a notice to open it on the server computer.

Step 4. Finish and sign in

When the wizard ends you go to the sign-in page. Sign in with the administrator you just created and prepare your organization:

  1. 관리 (Admin) → 부서 (Departments): add departments
  2. 직위·서열 (Positions and ranks): review (defaults exist and can be edited)
  3. 사원 (Employees): add staff, or import a CSV
  4. 규정·전결 (Approval rules): set each department's approval line

Details are in the Administrator guide.

For administrators: setup without the wizard 
echo 'your-password-here' > pw.txt
e-approval-kr setup --admin-id admin --admin-name 관리자 --password-file pw.txt
# delete pw.txt right after use
e-approval-kr serve --host 127.0.0.1 --port 8130

Use --host 0.0.0.0 to allow other PCs. In service installs the address is part of the service configuration, so change it with the wizard (or the configuration file) and restart the service. Health check: GET /healthz.

Setting up when the server has no screen: connect with SSH or remote desktop and open 127.0.0.1:8130/setup in a browser on the server, or use the CLI method above.

Publishing safely with HTTPS

If staff connect over the office network or from outside (home, mobile), put an HTTPS reverse proxy in front. The proxy handles encryption; e-approval-kr keeps listening on 127.0.0.1:8130.

For administrators: Caddy example
  1. Point a domain (for example approval.example.com) at the server and open ports 80 and 443.
  2. Set the environment variables GYEOLJAE_TRUST_PROXY=1 and GYEOLJAE_COOKIE_SECURE=1. Enable them only behind a proxy; on a directly exposed server they let attackers fake their IP and bypass login limits.
  3. Caddyfile:
    approval.example.com {
    reverse_proxy 127.0.0.1:8130
}
    See also deploy/caddy/Caddyfile in the repository. Caddy obtains the certificate automatically.

Alternatives: Cloudflare Tunnel (no port forwarding), or the server's own HTTPS (serve --https cert.pem key.pem). See docs/DEPLOY.md.
