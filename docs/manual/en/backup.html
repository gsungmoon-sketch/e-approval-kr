Backup and restore

A backup is a single zip file containing all documents, attachments and staff data. It can be made while the server is running.

Automatic backups

When you choose a backup folder in First setup, the server checks every hour and makes one backup per day, named e-approval-kr-YYYYMMDD-HHMMSS.zip, keeping only the latest 14 files of that name pattern (other files are never touched). The first backup appears within an hour after setup. To change how many are kept, set "backup_keep" (1-365) in server.json in the data folder and restart the service. Use a folder on a different disk from the server. Copying a backup to an external drive or another PC once a week is even safer.

Good habitNow and then open the backup folder and check that dated files keep appearing.

Manual backup

For administrators
e-approval-kr backup 2026-11-13.zip
To give the data location explicitly: e-approval-kr --data <data-folder> backup file.zip
Backup files are sensitiveThey contain documents and personal data. Keep them in encrypted storage (for example a password-protected external drive) and do not let others open them.

Restoring

  1. Stop the server (stop the Windows service / sudo systemctl stop e-approval-kr).
  2. Restore into an empty folder. It will not restore on top of existing data. Do not delete the old data folder; rename it and keep it.
  3. When restoring finishes, the audit log is verified automatically.
  4. Make the service use the restored folder (or put it at the old location) and start the server.
For administrators
e-approval-kr restore 2026-11-13.zip --to /path/to/new-empty-folder
For the data folder of service installs see Installation. On Linux, set the folder owner to the e-approval-kr user after restoring (sudo chown -R e-approval-kr: folder).

Keeping the audit head

The audit log is a chain of linked hashes. Someone who can edit the data folder freely could rebuild the whole chain. If you regularly write down the current head (number and hash) somewhere else, even that attempt is caught.

For administrators
e-approval-kr export-audit-head              # prints number and hash; store elsewhere
e-approval-kr check-audit-head <number> <hash>   # confirm the stored value is still in the chain
e-approval-kr -u admin verify-audit          # verify chain and completed documents

Suggested routine: store the head and run verification once a month.

Upgrading

Installing a newer version keeps your data. Still, always back up first.

  1. Back up. Make a manual backup and copy it somewhere safe.
  2. Pick a quiet time (after work) and tell staff. The server stops briefly.
  3. Download and run the new installer, the same way as the first time.
    • Windows: run the new setup-<version>-win-x64.exe (same SmartScreen steps). No need to uninstall first.
    • macOS: install the new .pkg.
    • Linux: unpack the new tar.gz and run sudo ./install.sh (add --lan again if you used it before).
    • pyz: replace the file and run it.
    • Docker: build the new image and start the container again with the same volume.
  4. Sign in, check that recent documents are there, and open /healthz.
  5. If something goes wrong, reinstall the previous version or restore the backup.
Settings are keptBind address, port and backup folder live in server.json in the data folder, so they survive an upgrade. The installer does rewrite the service definition, though (on Linux give --lan / --port again as the first time), so check once after upgrading that other PCs can still connect.
For administratorsRight after upgrading run e-approval-kr -u admin verify-audit to confirm the audit log is intact.
