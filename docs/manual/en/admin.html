Administrator guide

When you sign in as an administrator the Admin (관리) menu appears: Employees (사원) / Departments (부서) / Positions and ranks (직위·서열) / Approval rules (규정·전결) / Forms (양식) / Change requests and settings (변경요청·설정) / Outgoing mail (외부 메일) / Audit log (감사로그) (CSV import is at the bottom of the Employees screen). Administrators manage staff, rules and audit, but have no right to read other people's document bodies.

About the CLIRun the commands below on the server computer. The command is e-approval-kr for installed packages and gyeol when installed from source (same program). On Linux and macOS service installs use sudo e-approval-kr-admin command..., which runs as the service account with the right data location (e.g. sudo e-approval-kr-admin -u admin emp list); running the CLI directly as root can leave data files with the wrong owner. On Windows use Admin tool (관리 도구) from the Start menu. -u ID only says who is acting; it is not authentication (so the CLI must be reachable only by operators of the server). Choose the data location with --data or GYEOLJAE_DATA. Every command supports --json.

1. Order of setup

  1. Departments, 2. Positions and ranks, 3. Employees, 4. Approval rules, 5. (optional) adjust forms, 6. outgoing mail.

2. Departments

Under Admin → Departments (부서) register a department code (letters, e.g. DEV) and a name (e.g. 개발팀). You can rename, disable and re-enable. Disabling keeps existing documents.

For administrators
e-approval-kr -u admin dept add DEV 개발팀
e-approval-kr -u admin dept list

3. Positions and ranks

A position has a code (lowercase letters first), a name and a rank (its level). Ranks decide who is above whom in approval lines and final-approval limits. Add or edit them to fit your company. Granting a department-head-level position can require two-person approval (below).

4. Employees

Under Admin → Employees (사원) you add and edit staff, move departments, change positions, and set active / on leave / retired.

  • If you leave the employee number empty it is issued automatically (hire date YYMMDD plus a serial number, e.g. hired 2026-11-13 gives 26111301). The default sign-in ID is the employee number.
  • The temporary password is shown only once when you add the person. Pass it on right away; the employee changes it at first sign-in.
  • Setting someone to retired blocks sign-in; documents and records are kept.
  • Bulk CSV import: use the import function on the employee screen. Column names: 사번 (employee no.), 이름 (name), 부서 (department), 직위 (position), 아이디 (ID), 이메일 (email), 전화 (phone), 입사일 (hire date), 상태 (status), 직책 (title). Check the preview for errors first, then apply. UTF-8 and Excel (CP949) files both work. Export is also available.
  • Password reissue: create a new temporary password from the employee screen or the CLI.
For administrators
e-approval-kr -u admin emp add --name 홍길동 --dept DEV --position 팀원 --hired 2026-11-13
e-approval-kr -u admin emp import staff.csv           # preview
e-approval-kr -u admin emp import staff.csv --apply   # apply
e-approval-kr -u admin emp resetpw 26111301
e-approval-kr -u admin emp retire 26111301
e-approval-kr -u admin setting set emp_digits 3     # 3-digit serial in new numbers

5. Approval rules (per department)

Under Admin → Approval rules (규정·전결) set rules for each department and document type (general 일반 / expense 지출 / leave 휴가). A department with no rule uses a "free approval line" where the drafter builds the line.

ItemMeaning
Approval linePositions in order, e.g. 팀장?, 부서장, 대표. A question mark (?) means "skip if nobody holds this position"; @ID names a specific person.
Final-approval limit (전결)Amount limit per position, e.g. 부서장:100만, 임원:500만 (만 = 10,000 won). If the amount is at or below the limit, approval ends at that position.
Allow extra approversWhether the drafter may add more people to the line (yes/no).
Required CCPeople (IDs) who must always be copied, e.g. HR.
Delegation rulesWhether delegation is allowed, same department only, minimum position of the delegate, maximum days.
  • Rules are versioned. A change applies to new submissions; documents in progress keep the rule they were submitted under.
  • Use preview to see "who approves for this department, type and amount" before applying.
  • The amount comes automatically from the form's money field (table total).
For administrators
e-approval-kr -u admin policy edit DEV --type 지출 --line "팀장?, 부서장, 대표" --jeon "부서장:100만" --cc hr
e-approval-kr -u admin policy deleg DEV --allowed yes --same-dept yes --max-days 14
e-approval-kr -u admin policy preview --dept DEV --type 지출 --amount 150만
e-approval-kr -u admin policy show DEV ; e-approval-kr -u admin policy history DEV
e-approval-kr -u admin policy clear DEV      # remove rules (free approval line)
--type takes the Korean type names shown by policy show (일반, 지출, 휴가).

6. Managing forms

Under Admin → Forms (양식) you can list forms, create, copy, edit and disable them. It is easiest to copy one of the 10 built-in forms and change the copy.

Form properties

PropertyDescription
Name, codeThe code starts with a lowercase letter (e.g. hr_memo).
Category일반 (general) / 보고 (report) / 재정 (finance) / 인사 (HR) / 대외 (external)
Approval type (doc_type)general / expense / leave — decides which approval rule applies
Retention1년 / 3년 / 5년 / 10년 / 준영구 (quasi-permanent) / 영구 (permanent)
Departments allowedEmpty means all departments
Required CC departmentsThat department's head is copied automatically
Document number prefixUp to 8 letters/digits/Hangul; empty uses the department code

Field types

typeOn screenNotes
textOne-line text (한 줄 글)max characters (default 200)
textareaMulti-line text (여러 줄 글)max default 2000, up to 4000
numberNumber (숫자)
moneyAmount (금액)The form's total amount is used for final-approval limits.
dateDate (날짜)
daterangePeriod (기간)workdays:true counts working days only; half_field makes a half day 0.5
selectChoice (선택)options list (no duplicates, up to 30)

A form can have up to 30 fields. A field key starts with a lowercase letter and is at most 24 characters. Common properties: key, label, required, help.

  "category": "인사",
  "doc_type": "general",
  "retention": "3년",
  "prefix": "EDU",
  "fields": [
    {"key": "course", "label": "교육명", "type": "text", "required": true},
    {"key": "period", "label": "교육 기간", "type": "daterange", "required": true},
    {"key": "kind", "label": "구분", "type": "select", "options": ["사내", "사외"]},
    {"key": "items", "label": "비용 내역", "type": "table",
     "columns": [
       {"key": "item", "label": "항목", "type": "text"},
       {"key": "qty", "label": "수량", "type": "number"},
       {"key": "price", "label": "단가", "type": "money"},
       {"key": "amount", "label": "금액", "type": "money", "calc": "qty*price"}],
     "sum": ["amount"]},
    {"key": "proof", "label": "신청서 첨부", "type": "file", "min_files": 1}
  ]
}

The web form editor works with the same structure (screen details may differ between versions).

Versions

Editing a form creates a new version. Documents already drafted keep the version they were written with. Do not delete forms you no longer need; disable them.

For administrators
e-approval-kr -u admin form list
e-approval-kr -u admin form copy general hr_memo --name "인사 품의"
e-approval-kr -u admin form edit hr_memo definition.json    # new version
e-approval-kr -u admin form add edu definition.json

7. Document number format

The number is issued at final approval, so there are no gaps. Default: {dept}-{year}-{seq} (e.g. DEV-2026-0001). Placeholders: {dept} department code, {year} four-digit year, {yy} two-digit year, {prefix} form prefix (department code if none), {seq} serial number.

For administrators
e-approval-kr -u admin setting list
e-approval-kr -u admin setting set doc_number "{prefix}-{year}-{seq}"
e-approval-kr -u admin setting set show_contacts on   # show email/phone in the org chart
setting list shows the current format string. Free-form drafts (without a form) are off by default: while any form is enabled, every draft must start from a form, so an expense cannot be filed as a general document to dodge the 전결 limit. Turn on only if needed: setting set allow_freeform on. A new format applies to documents completed from then on; numbers already issued do not change.

8. Two-person approval

When on, important changes such as approval-rule changes, granting administrator rights, and granting department-head-level positions only take effect after another administrator approves. This guards against one person's mistake or misuse. Turn it on when you have two or more administrators. Pending items appear under Admin → Change requests and settings (변경요청·설정), where another administrator approves or rejects them.

For administrators
e-approval-kr -u admin setting set two_person on
e-approval-kr -u admin2 change list
e-approval-kr -u admin2 change approve <id>   # asks for your own password in a terminal
e-approval-kr -u admin2 change approve <id> --password-file pw.txt   # for scripts (first line = password, '-' = stdin)
The requester cannot approve their own request; only another administrator can. On the CLI that administrator must enter their own password to approve or reject. Two-person approval cannot be switched on with fewer than two administrators.

9. Outgoing mail (SMTP)

It is off by default. When on, approval-arrived / completed / rejected notices are emailed to the address in each employee's record. Sending internal mail to outside addresses must be allowed separately and has hourly limits. There is no incoming mail server feature (sending only).

  1. Open Admin → Outgoing mail (외부 메일).
  2. Enter your mail provider's SMTP server, port (e.g. 587), security (STARTTLS), user name, password and sender address. Google Workspace needs an app password.
  3. Use the test send (시험 발송) to check, then switch it on.
WarningThe SMTP password is stored in smtp.json in the data folder. Keep the data folder and backup files away from unauthorized people.
For administrators
echo 'app-password' | e-approval-kr -u admin smtp set --host smtp.example.com --port 587 --security starttls \
   --user mailer@example.com --from-addr mailer@example.com --from-name Approval --password-stdin --enabled on --notify-approvals on
e-approval-kr -u admin smtp test someone@example.com   # sends one test mail
e-approval-kr -u admin mail flush      # send the queue now (the web server also sends every 30 seconds)
With --allow-external-mail on internal mail may also be sent to outside addresses (hourly limits: --rate-per-hour, --user-external-per-hour).

10. Audit log and verification

Under Admin → Audit log (감사로그) every state change (submit, approve, reject, permission changes, ...) is recorded in a hash chain. Completed documents also get a content hash, so secret edits show up in verification.

  • Run verification regularly (for example monthly).
  • For stronger protection store the "chain head" somewhere else (another PC, email, paper). This even catches someone with write access to the data folder rebuilding the whole chain. See Backup and restore.
For administrators
e-approval-kr -u admin verify-audit
e-approval-kr export-audit-head
e-approval-kr -u admin audit --help
