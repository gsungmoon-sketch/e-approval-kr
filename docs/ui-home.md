# 첫 화면(홈)·메뉴 설계 — 시나리오 먼저

원칙: 로그인하면 **"오늘 내가 할 일"이 먼저** 보인다. 모든 화면은 서버 렌더링(자바스크립트 없음), 한국어,
폭 360px 휴대폰에서도 가로 스크롤 없이 쓴다. 각 단계마다 사용자가 **무엇을 보고(인지)**, **다음에 무슨 일이 생길지
예측**할 수 있고, **실수해도 안전**해야 한다.

## 1. 화면 구조
```
┌──────────┬───────────────────────────────────────────────┐
│ 결재      │ 공지사항 (고정 📌 먼저, 최근 5, 3일 내 새 글 N)    │
│ 홈        ├───────────────────────────────────────────────┤
│ 결재 (3)  │ [✍ 기안하기: 일반 | 지출 | 휴가]  [검색____][찾기] │
│ 문서함    ├──────────────────────┬────────────────────────┤
│ 게시판    │ 결재대기 3  (오래된 순) │ 결재진행 2 (현재 결재자) │
│ 자료실    │ 결재완료 (최근)         │ 반려 1 (다시 올릴 것)    │
│ 쪽지 (5)  ├──────────────────────┴────────────────────────┤
│ 조직도    │ 쪽지 안 읽음 5 · 참조 2 · 임시저장 1              │
│ 설정      └───────────────────────────────────────────────┘
│ 관리*     (*관리자만)
└──────────┘
휴대폰: 왼쪽 메뉴 대신 아래 탭 [홈][결재 3][게시판][쪽지 5][전체메뉴]
```
- 결재 하위: 결재대기 · 진행 · 완료 · 반려 · 참조 · 기안함(임시저장/회수)
- 문서함: 부서 문서함(완료 + 부서 공개 문서) · 내 보관함(개인 폴더)
- 게시판: 공지사항(관리자·부서장 작성, 관리자 고정) · 자유게시판
- 자료실: 전사 자료실(누구나 읽기, 부서장·관리자 올리기) · 우리 부서 자료실(부서원 읽기/올리기). 같은 이름을 올리면 **새 판**(덮어쓰기 없음)
- 설정: 비밀번호 변경 · 대결(위임) 설정
- 숫자 배지: 결재대기(내 차례 + 대결로 넘어온 것), 쪽지(안 읽음)

## 2. 역할별 시나리오
### 2-1. 팀원(기안자) — 아침에 접속
1. 로그인 → **홈**. 인지: 공지 맨 위 고정글, "결재대기 0 / 결재진행 2 / 반려 1". 예측: 반려 1건은 고쳐서 다시 올려야 함.
2. 반려 카드의 문서 클릭 → 반려 사유가 이력 맨 위에 보임 → [수정] → 고친 뒤 [상신]. 안전: 반려 상태에서만 수정 가능, 상신 전 결재선 미리보기 링크.
3. [✍ 기안하기 › 지출] → 종류가 미리 고른 양식으로 열림, 금액 입력, 결재선은 규정이 자동 구성(미리보기). 안전: 임시저장 가능, 제목·금액 검증 오류는 입력값을 잃지 않는 문구로 안내.
4. 결재진행 카드에서 "현재 결재자: 박개발 부서장" 확인 → 오래 걸리면 쪽지 보내기(조직도 → 이름).
5. 자료실 › 우리 부서 → 양식 파일 내려받기. 같은 이름 새 판 올리면 이전 판도 이력에 남음.
### 2-2. 부서장(결재자)
1. 로그인 → 홈의 **결재대기 카드가 오래된 순** — 가장 오래 기다린 문서가 맨 위(경과 일수 표시).
2. 문서 열기 → 본문·첨부 확인 → 의견 입력 → [승인]/[전결 승인]/[반려]. 예측: 승인하면 다음 결재자에게 쪽지, 마지막이면 문서번호 발급. 안전: 그 사이 기안자가 고쳤으면 "변경되었습니다" 로 거부(rev).
3. 출장 전 설정 › 대결 → 기간·대결자 지정(부서 규정 범위 안에서만).
4. 부서 문서함에서 부서 공개 완료 문서 열람. 공지 작성 가능.
### 2-3. 관리자
1. 로그인 → 홈(관리자도 결재 당사자일 수 있음) + 왼쪽 메뉴 맨 아래 **관리**.
2. 관리 › 사원 등록/CSV → 임시 비밀번호를 한 번만 보여 줌 → 전달. 관리 › 결재규정 → 미리보기로 확인 후 저장.
3. 게시판에서 공지 **고정/해제**. 전사 자료실에 규정집 업로드.
4. 관리 › 감사로그 → 무결성 검증. 관리자는 남의 문서 본문을 보지 못함(권한 경계).

## 3. 예외 상황
| 상황 | 화면 | 안전장치 |
|---|---|---|
| 문서가 하나도 없음(신입) | 카드마다 "없음" + 첫 기안 안내 문구, 기안하기 버튼은 그대로 | 빈 화면 대신 다음 행동 제시 |
| 문서가 많음 | 카드는 최근/오래된 5건 + "전체 보기(N)" 링크 → 문서함 목록(최대 200, 검색 권장) | 홈이 길어지지 않음 |
| 세션 만료(8시간) | 다음 클릭 시 로그인 화면 + "세션이 만료되었습니다", 로그인하면 원래 보던 화면으로(`next`, 내부 경로만) | 작성 중 POST 는 CSRF 실패 → "새로고침 후 다시" (입력값은 브라우저 뒤로가기로 복구) |
| 휴대폰 폭 | 왼쪽 메뉴 숨김 → 아래 탭 5개, 카드 1열, 표의 덜 중요한 열 숨김 | 가로 스크롤 없음 |
| 임시 비밀번호(첫 로그인/초기화) | 모든 주소가 비밀번호 변경 화면으로, 안내 문구 | 바꾸기 전엔 아무 기능도 못 씀 |
| 휴직/퇴사 계정 | 비밀번호가 맞으면 "사용 중지된 계정입니다(휴직·퇴사) — 관리자에게 문의", 틀리면 일반 오류 | 비밀번호를 모르는 사람에게는 계정 상태를 알려 주지 않음 |
| 권한 없는 문서·자료 주소 직접 입력 | "없거나 권한이 없습니다" (존재 숨김) | |
| 자료실 위험 파일 | 허용 확장자만, 20MB 상한, 저장명은 번호, 내려받기는 항상 첨부(attachment) | 경로 탈출·스크립트 실행 불가 |
| 쓰기 권한 없는 자료실 | 올리기 폼 자체를 숨김 + 서버에서도 거부 | |

## 4. CLI 대응(CLI 먼저)
- `gyeol -u kim home --json` — 홈 카드 데이터 그대로
- `gyeol -u kim files list [--org|--dept DEV]`, `files upload 파일 [--org] [--note]`, `files versions ID`, `files get ID [--version N] -o 경로`, `files delete ID`
- `gyeol -u kim folder list|create 이름|add 폴더ID 문서ID|remove|show 폴더ID|delete`, `list --box dept`
- `gyeol -u admin board pin 글ID [--off]`
